# dsh-setup

My DeepSeek Harness setup: the desktop profile overlay and the personal skills.
No credentials, no sessions, no machine identity live here.

## Contents

| Path | What it is |
|---|---|
| `profiles/desktop/cordis.patch.yml` | Profile patch: default model, UI preferences |
| `profiles/desktop/cordis.yml` | Composed profile root (regenerated by the app) |
| `profiles/desktop/package.json` | Profile manifest: bundles plus `dsh-shepherd` |
| `profiles/desktop/pnpm-workspace.yaml` | pnpm settings for the profile |
| `skills/` | Personal skills: branch context, PR workflow, audits, reviews |
| `install.sh` | Copies this setup into `$DSH_HOME` without overwriting by default |
| `sync.sh` | Two-way sync: `push` from the live setup, `pull` into it, `check` for secrets |

## Skills

| Skill | Use |
|---|---|
| `branch-context` | Branch-local brief, decisions log, and session handoffs |
| `adopt-pr` | Bootstrap branch context on an existing PR |
| `pushing-commits-to-the-repo` | Open and advance a PR: metadata, review gate, CI, triage |
| `pre-push-review` | Fresh read-only reviewer under a three-call budget |
| `complete-partial-pr` | Decide whether a narrow patch completes the contract |
| `poweruser-feature-audit` | External research, ideal test suite, gap analysis |
| `docs-parity-reviewer` | Documentation parity gate before merge |
| `file-followup-issue` | Park verified out-of-scope work as an issue |
| `refresh-issue-brief` | Re-fetch issue activity into the brief |
| `i-have-adhd` | Response shape: result first, no preamble, structured asks |

The bundle `dsh-shepherd` provides the matching tools, the reviewer preset, and `/be-terse`.

## Install

Prerequisites: DeepSeek Harness desktop, `git`, `gh`, and a checkout of `dsh-shepherd`.

```bash
git clone https://github.com/rohaquinlop/dsh-setup.git
cd dsh-setup
./install.sh
```

`install.sh` copies the skills into `$DSH_HOME/skills` and the profile files into
`$DSH_HOME/profiles/desktop`. It never overwrites an existing file unless you pass `--force`.
It substitutes the `dsh-shepherd` path in the profile manifest:

```bash
DSH_SHEPHERD_PATH=/path/to/dsh-shepherd ./install.sh
```

The default is `$HOME/opensource-projects/dsh-shepherd`.

After installing, restart the app or let the profile reload. Then confirm that
`plugin_manager list_plugins` shows the `dsh-shepherd` rows and the skill catalog lists the ten
skills.

If `dsh-shepherd` is not installed yet, either install it from the app:

```
plugin_manager { action: "install_bundle", target: "/path/to/dsh-shepherd" }
```

or remove `dsh-shepherd` from `profiles/desktop/package.json` before installing this profile.

## Two computers

The repository is the shared copy. Each computer keeps its own harness home and its own
`dsh-shepherd` checkout path.

**First time on a computer**

```bash
git clone https://github.com/rohaquinlop/dsh-setup.git
cd dsh-setup
DSH_SHEPHERD_PATH=/path/to/dsh-shepherd ./install.sh
```

**After changing something in the harness**

```bash
cd dsh-setup
./sync.sh push        # copies skills and profile files here, rewrites the bundle path, scans
git add -A && git commit -m "..." && git push
```

**On the other computer**

```bash
cd dsh-setup
git pull
./sync.sh pull        # overwrites live skills and profile files with the repository copy
```

`sync.sh push` removes repository skills that no longer exist live. `sync.sh pull` does not delete
extra live skills; remove those by hand.

The bundle path is stored as `link:__DSH_SHEPHERD__` and substituted per machine by `install.sh`
or `DSH_SHEPHERD_PATH`. A machine that keeps the checkout elsewhere exports that variable.

## Profile choices

- Default model: `deepseek-flash` at `max` reasoning effort.

## Deliberately excluded

| Path | Why |
|---|---|
| `$DSH_HOME/.credentials.yaml` | API credentials |
| `$DSH_HOME/.anonymous-user-id` | Machine identity |
| `$DSH_HOME/sessions/` | Conversation logs |
| `$DSH_HOME/storages/` | Cached session and workspace state |
| `$DSH_HOME/profiles/*/node_modules/` | Installed packages and symlinks |
| `$DSH_HOME/profiles/*/.plugin-manager/` | Install logs |

The profile manifest carries a placeholder where the `dsh-shepherd` checkout lives. No absolute
home path is committed.

## Updating

Edit the live files under `$DSH_HOME`, then copy them back here and commit:

```bash
cp -R "$HOME/.dsh/skills/." skills/
cp "$HOME/.dsh/profiles/desktop/cordis.patch.yml" profiles/desktop/
cp "$HOME/.dsh/profiles/desktop/cordis.yml" profiles/desktop/
cp "$HOME/.dsh/profiles/desktop/pnpm-workspace.yaml" profiles/desktop/
```

Rewrite the `dsh-shepherd` dependency back to `link:__DSH_SHEPHERD__` before committing.

## Secrets check

The repository contains no key, token, password, private key, email address, or absolute home path.
Run `./scripts/scan-secrets.sh` before every push to re-check.
